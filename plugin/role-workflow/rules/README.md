# 에이전트 규칙 진입점

role-workflow가 제공하는 AI 에이전트(Claude Code, Codex 등) 공통 규칙의 진입점이다. 작업 시작, 문맥 압축 복구, 세션·모델 교대 때마다 이 파일과 맡은 역할의 규칙 문서를 실제로 다시 읽는다.

## 1. 읽을 문서

| 상황                              | 읽을 문서                                                           |
| --------------------------------- | ------------------------------------------------------------------- |
| 항상                              | `00-common.md`                                                      |
| 기획설계 역할(연합개발 plan 대화) | `10-planning.md`, `30-verification.md`, `40-paseo-role-workflow.md` |
| 구현 역할(연합개발 execute 대화)  | `20-implementation.md`, `40-paseo-role-workflow.md`                 |
| 검증 역할                         | `30-verification.md`, `20-implementation.md`                        |
| 일반개발(대화 하나가 전부 맡음)   | `00-common.md` 3.4절, 그다음 단계마다 10 → 20 → 30                  |

역할이 지정되지 않았으면 `00-common.md` 3절로 운영 모드와 역할을 정하고 시작한다.

## 2. 상시 규칙 (요약 — 원본은 각 문서)

1. **역할 경계:** 기획설계는 제품 코드를 고치지 않고(승인된 푸시만 예외), 구현은 수락 기준·수락 시험을 고치지 않으며, 검증은 코드를 고치지 않는다. 최종 완료 판정은 검증 역할만 한다.
2. **사실 구분:** `[확인] [제안] [가정] [미확정]`, 하지 않은 것은 `[미실행]`. 근거 없는 수치·현황·검증 결과를 만들지 않는다.
3. **SSOT:** 정보마다 공식 원본은 하나다(`00-common.md` 6절). 같은 규칙을 다른 파일에 복사하지 않는다.
4. **위험도·증거 수준:** `00-common.md` 4절·5절이 유일한 기준이다.
5. **덧대기 금지:** 원래 책임 자리에서 고친다. 대체한 경로는 같은 변경에서 지운다.
6. **인계는 문서로:** `handoff.md` → `impl-report.md` → `verdict.md`. 대화 요약이나 기억으로 인계하지 않는다.
7. **멈춤:** 설계와 코드가 맞지 않거나, 승인 없는 계약·범위·안전 변경이 필요하거나, 규칙끼리 충돌하면 멈추고 근거와 선택지를 보고한다.
8. **완료 ≠ 푸시:** 푸시는 사용자의 명시 승인으로만 한다.

프로젝트별 경로·명령·위임 범위는 `project-settings.md`를 참고한다. 프로젝트 작업 폴더의 `AGENTS.md`·`CLAUDE.md`가 있으면 함께 읽는다.
