# role-workflow

Paseo의 일반개발·연합개발 작업 상태를 관리하는 플러그인입니다.

## 푸시가 필요 없는 작업 완료

조사·답변 또는 로컬 전용 변경을 마쳤고 원격에 보낼 변경이 없으면 사유와 함께 `작업상태: 푸시 불필요`를 보고합니다. 새 대화의 상태 지침에 포함되며, 기존 대화에서도 이 상태 줄을 입력할 수 있습니다.

이미 초록색으로 완료된 작업은 개발 작업 화면의 **푸시 불필요로 완료** 버튼으로 정리할 수 있습니다. 진행 중인 대화, 대기 중인 작업, 푸시 대상·승인 대기·실패 또는 미확인 실행이 남아 있으면 버튼은 완료 처리를 거부합니다. 미푸시 커밋 수나 원격 설정 유무만으로 자동 판정하지 않습니다.

- 파란색 제목에 `[푸시 불필요]`가 표시됩니다.
- 내부 상태 `no_push`는 실제 푸시를 검증한 `pushed` 및 `[PUSH]`와 구분됩니다. 푸시 실행 기록이나 원격 쓰기를 생성하지 않습니다.
- 설명만 이어가면 상태를 유지합니다. 새 수정·계획·진행 선언이 있으면 완료 상태가 해제됩니다.
- 기존 작업을 일괄 변경하거나 자동 보관 범위를 넓히지 않습니다. 기존 대화의 시스템 지침은 소급 변경되지 않습니다.

검증: `npm test`, `npm run typecheck`.


## 진행 방식과 최초 설정

새 연합개발의 계획 검증은 기본 최대 5회입니다. 첫 계획 전에는 검증·구현 담당과 배치를 고른 뒤 **이 설정으로 자동 진행**으로 저장합니다. 카드의 **선택됨 · 저장 전**은 아직 서버에 저장되지 않은 선택이며, 저장된 값과 일치하면 **설정 저장됨**으로 표시합니다. 카드와 대시보드의 **첫 계획 기다리는 중**은 설정 저장 뒤 계획 담당의 첫 계획 제출을 기다린다는 뜻입니다. 계획이 제출되면 기존 예약대로 검증을 시작하며, **검증 시작 대기**와 실제 **검증 중**을 구분합니다. 기존 작업에 저장된 검증 회차 한도는 유지합니다.

새 일반개발 작업(계약4 이상)은 최초 대화·모델·추론으로 직접 조사·구현·자체 검증합니다. 구현 담당이나 모델·추론을 추가로 묻지 않고 별도 실행 대화·자동 왕복을 만들지 않습니다. 결과는 자체 점검으로 표시하며 푸시는 별도 사용자 승인이 필요합니다.

새 대화는 질문·설명 요청이어도 첫 응답 전에 진행 방식(일반개발/연합개발)을 묻습니다. 모델이 묻지 않고 첫 응답을 마치면 대화에 **진행 방식 선택** 카드가 한 번 올라오며, 누르면 방식이 정해지고 계획 담당이 직전 요청을 그 방식으로 이어갑니다.

새 연합개발(계약5)은 최초 기획·설계·검증 담당을 유지하고, 구현 제품(Codex/Claude Code)·모델·추론을 선택기에서 고릅니다. 연합개발을 고르는 즉시 대화에 선택 카드가 올라가므로 계획을 기다리지 않고 바로 정할 수 있고, 계획 카드와 자동 작업 화면에서도 고를 수 있습니다. 선택기는 실제 카탈로그의 모델별 추론을 모두 보여주고 호스트가 조합을 검증합니다. 선택 전에 나온 계획은 보관했다가 선택 직후 한 번 전달합니다. 계획 담당 프롬프트에는 모델 카탈로그나 선택 질문이 들어가지 않습니다. 같은 제품·모델도 선택할 수 있고, 구현은 별도 대화에서 실행합니다. 계약4 작업은 기존 3질문 경로를 유지하며 화면 선택도 쓸 수 있습니다.

기존 실행 모델 질문 스위치는 이전 계약용입니다. 새 일반개발은 항상 질문 없이 최초 설정을 사용하고, 새 연합개발은 저장 추천값으로 선택을 건너뛰지 않습니다. 카탈로그 조회 실패나 미확인 답변은 선택 대기로 표시하며 기본값으로 몰래 실행하지 않습니다. 구현 담당이 이미 있는데 카탈로그 조회가 실패하면, 다음 계획 때 저장된 실제 답변으로 다시 확인하고, 그사이 선택 카드도 다시 보여 같은 제품 안에서 모델·추론을 고를 수 있습니다.

진행 중 방식 전환은 신규 작업에서 지원하지 않습니다. 다른 방식이 필요하면 새 작업으로 시작합니다. 기존 계약1/2/3의 대화·역할·모델·상태·선호는 자동 변환하지 않습니다. 계약3 일반개발은 이전의 역할 분리·자동 인계·검증 게이트를 유지합니다.

자동 왕복 한도는 연합개발 및 이전 역할 분리 작업에 적용합니다. 새 일반개발 실행 횟수 제한이 아닙니다. 재개 뒤 부분 이벤트의 수신 증거는 같은 응답의 전체 이력으로 확인하며, 실행 중 들어온 새 계획은 보존하고 기존 결과 검토 후 재확정하도록 안내합니다. 계획·실행을 병렬로 재시작하지 않습니다.

자동 압축은 연합개발과 기존 역할 분리 작업의 유휴 대화에서 수행합니다. 공통 `threshold` 권장은 0.7입니다. `claudeCompression` 권장은 비율 0.55·1M 한도 500,000토큰이며, 명시적 `null`은 공통 기준을 선택합니다. 정책이 켜져 있으면 Claude의 실제 컨텍스트 용량이 정확히 1,000,000일 때 `oneMillionTokenLimit` 토큰, 그 외 실제 용량은 `threshold` 비율로 판단합니다. 사용량·용량이 없거나 잘못되면 별도 Claude 정책은 압축하지 않습니다. 모델명으로 용량을 추정하지 않습니다. 신규 일반개발 Claude 단일 대화도 같은 압축 예약·중복 보호를 사용하며 역할 왕복·실행 대화 생성·자동 계속 메시지를 만들지 않습니다. 오류나 중단된 압축은 화면의 압축 복구·재시도로 확인합니다. Codex는 `codexCompression: "native"`에서 자체 압축에 맡기며 플러그인 사용량 기반 압축을 하지 않습니다. 설정이 없으면 Codex 자체 압축(`native`)을 사용하며, 명시적 `threshold`는 호환 모드를 유지합니다.

## 푸시

푸시는 사용자가 `/push` 또는 개발 작업 화면의 **푸시 대상 확인**에서 저장소·원격·브랜치·전체 커밋을 확인하고 승인하면 플러그인이 실행합니다. 에이전트는 `푸시대상:`을 보고하고 승인을 안내할 뿐 `git push`를 직접 실행하지 않습니다.

설정 **에이전트 셸 git push 차단**(`shellPushGuard`, 기본 켜짐)은 Claude·Codex 대화가 열릴 때마다 Git 전역 설정(`GIT_CONFIG_GLOBAL`)을 플러그인 상태 폴더의 `push-guard.gitconfig`로 바꿉니다. 이 파일은 사용자의 기존 전역 설정을 그대로 포함하고 모든 push URL을 존재하지 않는 전송으로 바꿔, fetch·commit 등은 그대로 두고 셸의 `git push`만 실패시킵니다. 권한 확인을 거치는 모드에서는 `git push` 권한 요청도 자동 거부합니다.

한계: 에이전트가 의도적으로 `GIT_CONFIG_GLOBAL`을 바꾸거나 저장소에 `pushurl`을 설정하는 우회, git이 아닌 도구로의 원격 쓰기는 막지 못합니다. 이런 실행은 턴이 끝난 뒤 푸시 감사가 기록합니다. 설정을 끄면 다음에 열리는 대화부터 차단이 빠집니다.

## 연합개발 구현 담당 배치

새 연합개발의 구현 담당은 기본으로 계획 담당과 **같은 워크스페이스의 탭**에서 일합니다. 같은 저장소에 파일을 고치는 다른 미완료 작업이 겹칠 때만 계획 담당 대화에 **따로 작업 공간 만들어 바로 시작 / 앞 작업이 끝나면 시작** 선택 카드가 뜹니다. 앞 작업은 응답 사이에 쉬고 있어도 미완료로 셉니다. 기다리면 겹치는 미완료 작업이 모두 끝나거나 보관·삭제·읽기 전용화된 뒤 자동으로 탭에서 시작합니다.

설정 **같은 폴더에 다른 작업이 있을 때**(`executorPlacement`)는 **매번 묻기**(`ask`, 기본) / **항상 따로 작업 공간**(`worktree`) / **항상 기다리기**(`wait`)입니다. 겹침이 없으면 어느 값이든 같은 탭으로 엽니다. 이전 `executorWorktree` 설정은 값에 관계없이 `ask`로 읽고, 다음 저장부터 옛 키를 지웁니다. 한 번 정한 배치는 교체 실행 담당과 재시작에서도 유지합니다.

- worktree는 계획 담당이 체크아웃한 브랜치의 현재 커밋에서 갈라집니다. 만든 직후 같은 Git 저장소(`git-common-dir`)인지 확인하고, 다르면 실행 담당을 만들지 않고 멈춥니다.
- 따로 작업 공간을 고르면 구현 담당은 사이드바의 별도 worktree 작업 행으로 보입니다. 그사이 기준 브랜치가 앞서면 구현 담당이 그 변경을 합치고 겹친 곳을 정리한 뒤 전체 시험을 다시 실행하며 계획 담당이 재검증합니다. 의도 판단이 필요한 충돌만 사용자에게 묻습니다.
- 새 worktree에는 기준 브랜치 이름을 저장합니다(옛 기록은 현재 checkout 사용). 푸시 준비 전에 기준 브랜치의 로컬 HEAD와 원격 추적 tip이 대상 커밋에 포함됐는지 읽기 전용으로 확인합니다. 앞서 있거나 확인할 수 없으면 승인 준비를 막고 계획 담당에게 보완을 안내합니다. 구현 담당이 최신 기준을 worktree 브랜치에 merge한 뒤 충돌 정리·전체 재시험을 하고, 계획 담당이 재검증한 커밋으로 푸시 대상을 갱신합니다. rebase·force로 이력을 다시 쓰지 않습니다.
- 기준 브랜치가 원격에 없거나 추적 브랜치가 없으면 기준 브랜치를 원격에 한 번 푸시하거나 upstream을 설정하세요.
- 검증된 커밋을 `/push`로 푸시하면, 계획 담당 폴더가 같은 브랜치이고 빨리 감기가 가능할 때만 그 커밋으로 `git merge --ff-only`합니다. 검사 뒤 기준이 다시 전진해 빨리 감기가 불가능하면 최후 방어로 반영을 건너뛰고 사유를 표시합니다. 승인 전 보완과 푸시 거절 뒤 우회 금지의 구분은 [규칙 4절](rules/40-paseo-role-workflow.md#4-푸시)을 따릅니다.
- 작업 폴더가 저장소 최상위가 아니거나, 여러 저장소를 지정했거나, 분리된 HEAD이거나, Git 저장소가 아니거나, 연결이 worktree 생성을 지원하지 않으면 기다리기를 자동 적용하고 사유를 표시합니다. 이미 같은 폴더에서 일하던 작업의 교체 구현 담당은 그대로 같은 폴더를 씁니다.
- 설정 **푸시 후 따로 작업 공간 자동 정리**(`autoArchiveWorktree`, 기본 켜짐)는 푸시의 원격 반영과 계획 폴더 ff 반영을 확인한 뒤 worktree 작업 공간만 보관합니다. 일반 푸시 작업 자동 보관 설정과 별개이며 계획 담당의 줄은 유지합니다. 보관된 대화 기록은 Paseo 보관 목록에서 볼 수 있습니다.
- 커밋하지 않은 변경·파일, 반영되지 않은 커밋, 실행·권한 대기, 미정리 지시, 다른 대화·작업이 있거나 확인할 수 없으면 작업 공간을 보존합니다. `evidence/`는 먼저 플러그인 상태 폴더의 `evidence/<작업ID>/worktree/<workspaceId>/`에 복사하고 파일 수를 확인합니다. 복사 실패도 보관을 막습니다. 증거가 1000개 또는 200MB를 넘으면 대기하며, 복사할 때 연 파일의 식별 정보와 변경 여부를 확인합니다. Git이 무시하는 파일은 evidence/ 외에는 보존되지 않습니다.
- 정리 진행·결과를 영속 기록하고 재시작 뒤 이어서 확인합니다. 일시 조회 오류와 사용자가 고정한 작업 공간은 횟수 소모 없이 대기합니다. 디렉터리 없음·저장소 식별 불일치가 같은 원인으로 3회 이상 연속 확인되고 첫 확인 뒤 10분 이상 지나면 자동 정리를 멈추고 직접 보관 안내를 남깁니다. worktree 실행 공간은 자동 고정 대상에서 제외하고 계획 공간의 고정은 유지합니다. 기존 플러그인 소유 고정은 현재 고정 시각이 소유 기록과 일치할 때만 보관 직전에 해제하며, 해제를 확인하지 못하면 보존합니다. 보관 실패는 60초 이상 간격으로 최대 3회 시도하며 이후에는 직접 보관 안내를 남깁니다. 보존 판정(skipped)이나 정리 완료(done)는 자동으로 다시 시도하지 않습니다. 새 Paseo API나 직접 Git 삭제 명령은 사용하지 않습니다. 정리된 작업에서 새 구현을 시작하면 새 실행 대화를 만들고 현재 겹침에 따라 탭/별도 작업 공간/기다리기를 다시 결정합니다.
- 플러그인 밖에서 만든 연결 worktree도 일반 보관 전에 미커밋 변경과 HEAD의 실제 원격 포함을 확인하며, 확인하지 못하면 사유를 표시하고 보존합니다.
- assume-unchanged·skip-worktree 표시, submodule 상태 차이·미커밋 변경·원격에 없는 커밋, 반영되지 않은 HEAD reflog 커밋이 있으면 작업 공간을 보존합니다.
- 따로 작업 공간 정리가 끝나기 전에는 기존 자동 보관과 완료 정리에서도 해당 작업의 계획·구현 작업 공간을 모두 보존합니다. 새 구현 주기는 정리 상태를 초기화하며, 직접 보관해 디렉터리가 사라진 작업 공간도 새 실행 대화로 다시 배치합니다.
- 플러그인 밖에서 수동으로 편집하는 작업은 감지하지 않습니다.

## Paseo 호환 범위

`paseo-plugin.json`은 `>=0.15.0 <0.16.0`을 요구합니다. 개발용 `@getpaseo/*`는 지원 범위의 최저 버전인 0.15.0에 고정해 그보다 새 API를 쓰지 않게 합니다.

- 서버 이벤트는 0.15의 `addHook`으로 등록합니다(`agent.create.before`, `agent.open.before`, `agent.create.after`, `agent.turn.before`, `agent.turn.after`, `agent.permission.before`, `agent.permission.after`, `agent.archive.after`). 옛 `on`/`before` 등록은 Paseo에서 2027-04-30 이후 제거됩니다.
- 0.15의 `agent.turn.after`는 timeline을 비워 보냅니다. 끝난 턴은 대화 기록에서 다시 읽습니다.
- 화면은 `addScreen`·`addSidebarHeaderItem`(호스트의 `SidebarRow`)·`openScreen`으로 등록합니다. 폐기 예정인 `addSurface`/`addSidebarItem`/`openSurface`는 쓰지 않습니다. Paseo는 옛 사이드바 항목과 같은 id의 설정 키와 `/sidebar/<id>` 링크를 새 화면으로 이어 줍니다.
- 0.16이 나오면 변경점을 확인하고 테스트한 뒤 상한을 올립니다.

## 사장 지시서와 롤백

현재 설정은 `$PASEO_HOME/owner/policy.json`(기본 `~/.paseo/owner/policy.json`)의 권장값 차이로 저장합니다.
처음 로드할 때 기존 state.settings·옛 알림 키를 한 번 이관하고, 기존 파일은 보존합니다.
state.settings는 롤백용 동결 사본입니다. 옛 코드로 롤백하면 이관 이후 설정 변경은 사라집니다.
지시서가 깨지면 권장값으로 동작하며 오류·경로를 화면에 표시하고 저장을 거부합니다.
설정 화면은 읽은 revision을 보낼 때만 저장하며 충돌하면 새로 읽어야 합니다.
권장 프로필 목록은 shared/presets/profiles.json 하나이며 제품 모두 계획·구현을 할 수 있습니다.

지시서의 roleWorkflow는 설정 차이 객체, notifications는 알림 값 객체입니다.
두 묶음의 결정 날짜는 decisions.roleWorkflow.date와 decisions.notifications.date에 기록합니다.
migratedFrom은 이관 출처·시각·원래 settings의 SHA-256이며, 저장해도 이 기록을 유지합니다.
정책 JSON Schema의 설정 부분은 settingsValuesSchema에서 생성합니다. 검증 제약을 바꾸면
`tsx scripts/sync-policy-schema.mts`로 JSON을 동기화하고 Python 검증도 확인하세요.

신규 계약6은 브레인스토밍을 지원합니다. 파일을 바꾸지 않고 조사·논의한 뒤 일반개발·연합개발·개발 안 함을 고릅니다.
연합개발의 첫 계획은 화면에 보관되며, 그 계획을 확인하고 구현 제품·모델·추론을 고르면 전달됩니다.
계획이 교체·취소되면 다시 확인해야 합니다. 계약5 이하 작업의 선택·전달 동작은 유지합니다.
롤백은 계약6 작업에 보관 중인 계획이 없을 때 하는 것을 권장합니다. 이전 빌드에서는 첫 계획 승인 게이트와 브레인스토밍 표시가 사라집니다.
