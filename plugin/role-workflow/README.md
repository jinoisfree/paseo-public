# role-workflow

Paseo의 일반개발·연합개발 작업 상태를 관리하는 플러그인입니다.

## 푸시가 필요 없는 작업 완료

조사·답변 또는 로컬 전용 변경을 마쳤고 원격에 보낼 변경이 없으면 사유와 함께 `작업상태: 푸시 불필요`를 보고합니다. 새 대화의 상태 지침에 포함되며, 기존 대화에서도 이 상태 줄을 입력할 수 있습니다.

이미 초록색으로 완료된 작업은 개발 작업 화면의 **푸시 불필요로 완료** 버튼으로 정리할 수 있습니다. 진행 중인 대화, 대기 중인 작업, 푸시 대상·승인 대기·실패 또는 미확인 실행이 남아 있으면 버튼은 완료 처리를 거부합니다. 미푸시 커밋 수나 원격 설정 유무만으로 자동 판정하지 않습니다.

- 파란색 제목에 `[푸시 불필요]`가 표시됩니다.
- 내부 상태 `no_push`는 실제 푸시를 검증한 `pushed` 및 `[PUSH]`와 구분됩니다. 푸시 실행 기록이나 원격 쓰기를 생성하지 않습니다.
- 설명만 이어가면 상태를 유지합니다. 새 수정·계획·진행 선언이 있으면 완료 상태가 해제됩니다.
- 기존 작업을 일괄 변경하거나 자동 보관 범위를 넓히지 않습니다. 기존 대화의 시스템 지침은 소급 변경되지 않습니다.

검증: `npm test`, `npm run typecheck`.


## 진행 방식과 최초 설정

새 일반개발 작업(계약4 이상)은 최초 대화·모델·추론으로 직접 조사·구현·자체 검증합니다. 구현 담당이나 모델·추론을 추가로 묻지 않고 별도 실행 대화·자동 왕복을 만들지 않습니다. 결과는 자체 점검으로 표시하며 푸시는 별도 사용자 승인이 필요합니다.

새 대화는 질문·설명 요청이어도 첫 응답 전에 진행 방식(일반개발/연합개발)을 묻습니다. 모델이 묻지 않고 첫 응답을 마치면 대화에 **진행 방식 선택** 카드가 한 번 올라오며, 누르면 방식이 정해지고 계획 담당이 직전 요청을 그 방식으로 이어갑니다.

새 연합개발(계약5)은 최초 기획·설계·검증 담당을 유지하고, 구현 제품(Codex/Claude Code)·모델·추론을 선택기에서 고릅니다. 연합개발을 고르는 즉시 대화에 선택 카드가 올라가므로 계획을 기다리지 않고 바로 정할 수 있고, 계획 카드와 자동 작업 화면에서도 고를 수 있습니다. 선택기는 실제 카탈로그의 모델별 추론을 모두 보여주고 호스트가 조합을 검증합니다. 선택 전에 나온 계획은 보관했다가 선택 직후 한 번 전달합니다. 계획 담당 프롬프트에는 모델 카탈로그나 선택 질문이 들어가지 않습니다. 같은 제품·모델도 선택할 수 있고, 구현은 별도 대화에서 실행합니다. 계약4 작업은 기존 3질문 경로를 유지하며 화면 선택도 쓸 수 있습니다.

기존 실행 모델 질문 스위치는 이전 계약용입니다. 새 일반개발은 항상 질문 없이 최초 설정을 사용하고, 새 연합개발은 저장 추천값으로 선택을 건너뛰지 않습니다. 카탈로그 조회 실패나 미확인 답변은 선택 대기로 표시하며 기본값으로 몰래 실행하지 않습니다.

진행 중 방식 전환은 신규 작업에서 지원하지 않습니다. 다른 방식이 필요하면 새 작업으로 시작합니다. 기존 계약1/2/3의 대화·역할·모델·상태·선호는 자동 변환하지 않습니다. 계약3 일반개발은 이전의 역할 분리·자동 인계·검증 게이트를 유지합니다.

자동 왕복 한도는 연합개발 및 이전 역할 분리 작업에 적용합니다. 새 일반개발 실행 횟수 제한이 아닙니다. 재개 뒤 부분 이벤트의 수신 증거는 같은 응답의 전체 이력으로 확인하며, 실행 중 들어온 새 계획은 보존하고 기존 결과 검토 후 재확정하도록 안내합니다. 계획·실행을 병렬로 재시작하지 않습니다.

자동 압축은 연합개발과 기존 역할 분리 작업의 유휴 대화에서 수행합니다. 기본 `threshold`는 기존 공통 비율이며 Codex에도 적용됩니다. 선택적 `claudeCompression`은 기본 비활성(`null`)이고, 켜면 Claude의 실제 컨텍스트 용량이 정확히 1,000,000일 때 `oneMillionTokenLimit` 토큰, 그 외 실제 용량은 `threshold` 비율로 판단합니다. 사용량·용량이 없거나 잘못되면 별도 Claude 정책은 압축하지 않습니다. 모델명으로 용량을 추정하지 않습니다. 신규 일반개발 Claude 단일 대화도 같은 압축 예약·중복 보호를 사용하며 역할 왕복·실행 대화 생성·자동 계속 메시지를 만들지 않습니다. 오류나 중단된 압축은 화면의 압축 복구·재시도로 확인합니다. Codex는 `codexCompression: "native"`에서 자체 압축에 맡기며 플러그인 사용량 기반 압축을 하지 않습니다. 설정이 없는 이전 설치는 `threshold` 호환 모드를 유지합니다.

## 푸시

푸시는 사용자가 `/push` 또는 개발 작업 화면의 **푸시 대상 확인**에서 저장소·원격·브랜치·전체 커밋을 확인하고 승인하면 플러그인이 실행합니다. 에이전트는 `푸시대상:`을 보고하고 승인을 안내할 뿐 `git push`를 직접 실행하지 않습니다.

설정 **에이전트 셸 git push 차단**(`shellPushGuard`, 기본 켜짐)은 Claude·Codex 대화가 열릴 때마다 Git 전역 설정(`GIT_CONFIG_GLOBAL`)을 플러그인 상태 폴더의 `push-guard.gitconfig`로 바꿉니다. 이 파일은 사용자의 기존 전역 설정을 그대로 포함하고 모든 push URL을 존재하지 않는 전송으로 바꿔, fetch·commit 등은 그대로 두고 셸의 `git push`만 실패시킵니다. 권한 확인을 거치는 모드에서는 `git push` 권한 요청도 자동 거부합니다.

한계: 에이전트가 의도적으로 `GIT_CONFIG_GLOBAL`을 바꾸거나 저장소에 `pushurl`을 설정하는 우회, git이 아닌 도구로의 원격 쓰기는 막지 못합니다. 이런 실행은 턴이 끝난 뒤 푸시 감사가 기록합니다. 설정을 끄면 다음에 열리는 대화부터 차단이 빠집니다.

## 연합개발 구현 담당 배치

새 연합개발의 구현 담당은 기본으로 계획 담당과 **같은 워크스페이스의 탭**에서 일합니다. 같은 저장소에 파일을 고치는 다른 미완료 작업이 겹칠 때만 계획 담당 대화에 **따로 작업 공간 만들어 바로 시작 / 앞 작업이 끝나면 시작** 선택 카드가 뜹니다. 앞 작업은 응답 사이에 쉬고 있어도 미완료로 셉니다. 기다리면 겹치는 미완료 작업이 모두 끝나거나 보관·삭제·읽기 전용화된 뒤 자동으로 탭에서 시작합니다.

설정 **같은 폴더에 다른 작업이 있을 때**(`executorPlacement`)는 **매번 묻기**(`ask`, 기본) / **항상 따로 작업 공간**(`worktree`) / **항상 기다리기**(`wait`)입니다. 겹침이 없으면 어느 값이든 같은 탭으로 엽니다. 이전 `executorWorktree` 설정은 값에 관계없이 `ask`로 읽고, 다음 저장부터 옛 키를 지웁니다. 한 번 정한 배치는 교체 실행 담당과 재시작에서도 유지합니다.

- worktree는 계획 담당이 체크아웃한 브랜치의 현재 커밋에서 갈라집니다. 만든 직후 같은 Git 저장소(`git-common-dir`)인지 확인하고, 다르면 실행 담당을 만들지 않고 멈춥니다.
- 따로 작업 공간을 고르면 구현 담당은 사이드바의 별도 worktree 작업 행으로 보입니다. 같은 부분을 바꾸면 나중에 직접 합치는 작업이 필요할 수 있습니다.
- 검증된 커밋을 `/push`로 푸시하면, 계획 담당 폴더가 같은 브랜치이고 빨리 감기가 가능할 때만 그 커밋으로 `git merge --ff-only`합니다. 그렇지 않으면 건드리지 않고 직접 반영하라고 표시합니다.
- 작업 폴더가 저장소 최상위가 아니거나, 여러 저장소를 지정했거나, 분리된 HEAD이거나, Git 저장소가 아니거나, 연결이 worktree 생성을 지원하지 않으면 기다리기를 자동 적용하고 사유를 표시합니다. 이미 같은 폴더에서 일하던 작업의 교체 구현 담당은 그대로 같은 폴더를 씁니다.
- worktree 정리는 Paseo의 작업 보관(자동 보관 포함)을 따릅니다.
- 플러그인 밖에서 수동으로 편집하는 작업은 감지하지 않습니다.

## Paseo 호환 범위

`paseo-plugin.json`은 `>=0.15.0 <0.16.0`을 요구합니다. 개발용 `@getpaseo/*`는 지원 범위의 최저 버전인 0.15.0에 고정해 그보다 새 API를 쓰지 않게 합니다.

- 서버 이벤트는 0.15의 `addHook`으로 등록합니다(`agent.create.before`, `agent.open.before`, `agent.create.after`, `agent.turn.before`, `agent.turn.after`, `agent.permission.before`, `agent.permission.after`, `agent.archive.after`). 옛 `on`/`before` 등록은 Paseo에서 2027-04-30 이후 제거됩니다.
- 0.15의 `agent.turn.after`는 timeline을 비워 보냅니다. 끝난 턴은 대화 기록에서 다시 읽습니다.
- 화면은 `addScreen`·`addSidebarHeaderItem`(호스트의 `SidebarRow`)·`openScreen`으로 등록합니다. 폐기 예정인 `addSurface`/`addSidebarItem`/`openSurface`는 쓰지 않습니다. Paseo는 옛 사이드바 항목과 같은 id의 설정 키와 `/sidebar/<id>` 링크를 새 화면으로 이어 줍니다.
- 0.16이 나오면 변경점을 확인하고 테스트한 뒤 상한을 올립니다.
