# role-workflow

Paseo의 일반개발·연합개발 작업 상태를 관리하는 플러그인입니다.

## 푸시가 필요 없는 작업 완료

조사·답변 또는 로컬 전용 변경을 마쳤고 원격에 보낼 변경이 없으면 사유와 함께 `작업상태: 푸시 불필요`를 보고합니다. 새 대화의 상태 지침에 포함되며, 기존 대화에서도 이 상태 줄을 입력할 수 있습니다.

이미 초록색으로 완료된 작업은 개발 작업 화면의 **푸시 불필요로 완료** 버튼으로 정리할 수 있습니다. 진행 중인 대화, 대기 중인 작업, 푸시 대상·승인 대기·실패 또는 미확인 실행이 남아 있으면 버튼은 완료 처리를 거부합니다. 미푸시 커밋 수나 원격 설정 유무만으로 자동 판정하지 않습니다.

- 파란색 제목에 `[푸시 불필요]`가 표시되고 기존 사이드바의 ‘푸시 완료’ 접기 그룹에 포함됩니다. 선택 중이거나 고정된 작업은 기존 규칙대로 계속 보입니다.
- 내부 상태 `no_push`는 실제 푸시를 검증한 `pushed` 및 `[PUSH]`와 구분됩니다. 푸시 실행 기록이나 원격 쓰기를 생성하지 않습니다.
- 설명만 이어가면 상태를 유지합니다. 새 수정·계획·진행 선언이 있으면 완료 상태가 해제됩니다.
- 기존 작업을 일괄 변경하거나 자동 보관 범위를 넓히지 않습니다. 기존 대화의 시스템 지침은 소급 변경되지 않습니다.

검증: `npm test`, `npm run typecheck`.


## 진행 방식과 최초 설정

새 일반개발 작업(계약4)은 최초 대화·모델·추론으로 직접 조사·구현·자체 검증합니다. 구현 담당이나 모델·추론을 추가로 묻지 않고 별도 실행 대화·자동 왕복을 만들지 않습니다. 결과는 자체 점검으로 표시하며 푸시는 별도 사용자 승인이 필요합니다.

새 연합개발은 최초 기획·설계·검증 담당을 유지하고 진행 방식 답변 후 구현 제품(Codex/Claude Code)·모델·추론 3질문을 한 번의 질문 도구 호출로 제시합니다. 두 제품의 모델 ID와 모델별 지원 추론을 함께 안내하고 호스트가 조합을 검증합니다. 같은 제품·모델도 선택할 수 있고, 구현은 별도 대화에서 실행합니다. 추론 없음과 모델 기본값은 명시적 답변으로 구분하며 기본값은 카탈로그에서 확인될 때만 사용합니다. 부분 응답의 유효한 필드는 보존하고 누락·무효 필드만 다시 묻습니다.

기존 실행 모델 질문 스위치는 이전 계약용입니다. 새 일반개발은 항상 질문 없이 최초 설정을 사용하고, 새 연합개발은 저장 추천값으로 질문을 건너뛰지 않습니다. 카탈로그 조회 실패나 미확인 답변은 선택 대기로 표시하며 기본값으로 몰래 실행하지 않습니다.

진행 중 방식 전환은 신규 작업에서 지원하지 않습니다. 다른 방식이 필요하면 새 작업으로 시작합니다. 기존 계약1/2/3의 대화·역할·모델·상태·선호는 자동 변환하지 않습니다. 계약3 일반개발은 이전의 역할 분리·자동 인계·검증 게이트를 유지합니다.

자동 왕복 한도는 연합개발 및 이전 역할 분리 작업에 적용합니다. 새 일반개발 실행 횟수 제한이 아닙니다. 재개 뒤 부분 이벤트의 수신 증거는 같은 응답의 전체 이력으로 확인하며, 실행 중 들어온 새 계획은 보존하고 기존 결과 검토 후 재확정하도록 안내합니다. 계획·실행을 병렬로 재시작하지 않습니다.

자동 압축은 연합개발과 기존 역할 분리 작업의 유휴 대화에서 수행합니다. 기본 `threshold`는 기존 공통 비율이며 Codex에도 적용됩니다. 선택적 `claudeCompression`은 기본 비활성(`null`)이고, 켜면 Claude의 실제 컨텍스트 용량이 정확히 1,000,000일 때 `oneMillionTokenLimit` 토큰, 그 외 실제 용량은 `threshold` 비율로 판단합니다. 사용량·용량이 없거나 잘못되면 별도 Claude 정책은 압축하지 않습니다. 모델명으로 용량을 추정하지 않습니다. 신규 일반개발 Claude 단일 대화도 같은 압축 예약·중복 보호를 사용하며 역할 왕복·실행 대화 생성·자동 계속 메시지를 만들지 않습니다. 오류나 중단된 압축은 화면의 압축 복구·재시도로 확인합니다. Codex는 `codexCompression: "native"`에서 자체 압축에 맡기며 플러그인 사용량 기반 압축을 하지 않습니다. 설정이 없는 이전 설치는 `threshold` 호환 모드를 유지합니다.
